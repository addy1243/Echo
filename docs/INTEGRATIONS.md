# Integration setup and boundaries

## Wikimedia Commons audio

Search uses the public MediaWiki HTTPS API, limited to audio in the `Audio files of music` category tree. The response must declare `mediatype=AUDIO`, including Commons' `application/ogg` audio MIME type. Playback accepts only `upload.wikimedia.org` HTTPS URLs with explicit CC BY, CC BY-SA, CC0 or public-domain license URLs. Missing/unsupported licensing or creator metadata excludes a result. The original file is streamed, without transcoding or downloads. Commons is a small freely licensed catalog, not a substitute for the commercial music catalog. Category membership is maintained by Commons and may be incomplete or misclassified.

`CommonsProvider.search(query)` returns native-playable `Track`s. The UI must display `attribution`, link `licenseUrl`, and link `sourcePage`. Credits persist with the library track. User-provided attribution is rendered as plain text. File pages remain the authority for authorship and license conditions. See [MediaWiki image metadata](https://www.mediawiki.org/wiki/API:Imageinfo).

`SourceResolver.priority` persists an ordered subset of `local,youtube,commons`; an empty list disables playback sources. Upgrading adds YouTube to existing nonempty source preferences once, preserving disabled sources and an explicitly empty list. Local URIs require readable Android grants. `TrackMatcher.matches` compares recording IDs when available, otherwise normalized title/artist and a five-second duration tolerance. Matching is deliberately conservative and does not automatically send Spotify metadata to another service. Imported unavailable tracks can be manually replaced through the library UI.

## Spotify playlist files and Echo discovery

The user does not have Spotify Premium. Do not resume developer-account onboarding as a prerequisite for using Echo. Spotify's current development-mode owner Premium requirement and playlist access restrictions prevent promising general Spotify auto-sync, even for personal use. The normal Settings screen now directs users to file import; an existing session can still be disconnected. OAuth code/credentials are retained without exposing the connection flow.

In Library, choose **Import Spotify playlist file**. Supported UTF-8 inputs:

- Exportify track CSV: required `Track URI`, `Track Name`, `Artist Name(s)`; optional `Album Name` and `Track Duration (ms)` (legacy `Duration (ms)` also accepted). Quoted commas, double quotes, embedded newlines, CRLF and a BOM are handled. Extra export columns are ignored. Extract an individual CSV from an Export All ZIP first; ZIP and album-only exports are not supported. [Exportify format and instructions](https://github.com/watsonbox/exportify#export-format). Exportify account access remains an external dependency; its live login was not verified here.
- Spotify account-data `Playlist*.json`: root `playlists` array, each with `name` and `items[].track` (`trackName`, `artistName`, `albumName`, optional `trackUri`). Use only the playlist file from the downloaded package, not the entire private account archive. Podcast/local entries without a track object are skipped and counted. [Spotify account-data description](https://support.spotify.com/in-en/article/understanding-your-data/).

Imports contain metadata, not audio. Song order and duplicate occurrences are preserved. A repeated file creates new playlists instead of replacing edits; all playlists in one file commit transactionally or none do. Limits: 10 million characters, 1,000 playlists and 50,000 song occurrences. Malformed required track data fails the import without changing the library. Files are read locally and not uploaded. Imports are snapshots and do not automatically reflect Spotify changes.

Open an imported playlist and use **Find recording** to search YouTube for a song. Explicitly choosing a result replaces only that occurrence with the chosen playable YouTube track; the original metadata track remains in the library. The saved position and expected track ID are checked before replacement so a stale choice cannot replace a different song. Existing local-match behavior remains available. Echo does not automatically accept a cover or other recording as equivalent.

Home > **Discover** loads live YouTube Music searches. Discovery uses up to three artists from likes, recent listening and the library. It excludes known IDs and exact normalized title/artist duplicates and offers **Save mix to Library** as a new dated snapshot. This is a basic artist-search mix, not Spotify's recommendation engine; near-duplicate titles and uploader names can escape exact matching. **New music** searches for `new music releases YYYY-MM` using the current device month. Results can include older songs and are not a verified release-date feed. Results load on first opening and can be refreshed manually; no APK update is needed for newly searchable recordings. No background notification or daily scheduling is implemented.

Playlist **Smart shuffle · Echo** searches up to three playlist artists, removes playlist/recent matches, randomizes playable original occurrences and inserts one unique discovery after each group of up to three songs. It preserves the saved playlist and only replaces the playback queue when suggestions succeed. Playback's ordinary shuffle flag stays off to preserve the interleaved order. Unavailable metadata-only entries are skipped by playback; select recordings first. Network failures leave the playing queue unchanged and display an error; zero suggestions asks the user to try normal shuffle.

The existing source authorization, URL validation, bounded recovery and source availability limits remain applicable. No Spotify audio, preview extraction, borrowed credentials or automatic Spotify playlist synchronization is implemented.
## Key-free YouTube playback

Echo uses [NewPipeExtractor v0.26.5](https://github.com/TeamNewPipe/NewPipeExtractor/releases/tag/v0.26.5) for YouTube Music song search and fresh progressive audio stream resolution. No YouTube Data API key or Google account is needed. The previous Data API discovery client and API-key settings UI have been removed. Previously stored encrypted keys are left untouched but are no longer read by search/playback.

The design follows the separation used by Spotube: stable song metadata in the library, source extraction at playback time, and Echo's own Media3 queue. It does not embed Spotube or its Flutter/plugin runtime. `YouTubeProvider` and `YouTubeDownloader` contain extractor-specific code. Search results persist canonical watch URLs and provider-scoped video IDs, never expiring media URLs. Queue entries resolve lazily on the Media3 loader thread. A per-source cache refreshes near expiry, and a media HTTP403 permits at most one fresh source attempt; HTTP429 and extraction failures require user retry. Local files and Commons retain their existing paths. Likes, playlists, backup exports and queue restoration reuse existing Track storage without a schema migration. Spotify imports are not automatically matched to YouTube recordings.

Only recorded, available audio is selected. Original/default progressive audio uses HTTPS YouTube delivery hosts. There is no login, cookie import, captcha solver, paid/member content access or DRM support. An unavailable or changed source displays a failure. This is unofficial extraction; YouTube's API policies do not authorize ad blocking, separate audio or background API playback, and personal use does not remove service restrictions. See [YouTube policies](https://developers.google.com/youtube/terms/developer-policies).

### Updating a broken extractor

1. Check the provider error and upstream [NewPipeExtractor releases](https://github.com/TeamNewPipe/NewPipeExtractor/releases). Stop on rate limits; do not loop requests.
2. Update the pinned `newpipe` version in `gradle/libs.versions.toml`. Keep the restricted JitPack repository, required core-library NIO desugaring, and documented Rhino shrinker rules. Review upstream changes before changing adapters.
3. Run data/playback/app unit tests, debug build and lint. Build the release variant to verify shrinking. Run normal navigation/local-player regressions and the explicit live YouTube test on the emulator, demonstrating real advancing playback before calling the update working.
4. For an installable update, increment versionCode and use the same signing key per [UPDATES.md](UPDATES.md). Updating a Gradle dependency does not update an already installed APK.

NewPipeExtractor is **GPL-3.0-or-later**, unlike Spotube's root license. Its use introduces distribution obligations for combined builds, including corresponding source and license notices. Before distributing an APK, address the applicable whole-program GPL terms and dependency notices. This change does not publish an APK or declare a new license for the user's existing source. See [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## Verification limits

Deterministic tests cover matching, audio MIME/media-type validation, license URL validation, and OAuth state/expiry checks. A live public Commons API query for Chopin returned usable CC BY-SA 4.0 recordings and verified that recording attribution can differ from the composer field. A ranged HTTP request to the [Muriel Nguyen Xuan recording](https://commons.wikimedia.org/wiki/File:Muriel-Nguyen-Xuan-Chopin-valse-opus64-1.ogg) returned HTTP 206, application/ogg and an Ogg/Vorbis header when using Echo's descriptive User-Agent; the provider passes this header to Media3. This checks public URL availability, not Android playback. A subsequent opt-in Android service playback test searched the live catalog successfully but the selected Commons upload returned HTTP 429; the same public file returned 429 in a shell HTTP request. Native Commons playback therefore did not pass in this environment. Echo does not bypass server rate limits; retry only after the server's Retry-After interval or a later user attempt. Live OAuth, actual playlist grants, YouTube quota, device Keystore and HTTPS app-link verification require their own configured runtime checks. Source code and official API documentation alone do not verify those runtime behaviors.
