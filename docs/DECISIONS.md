# Decisions

- 2026-10-28: Prepare the owner-authorized combined `v0.2.0` GitHub release as Android 0.2.0/code11 and Windows 0.2.0, with exact corresponding source and checksums. Windows advances the 0.1.0 preview so existing update checks can discover it. Public Windows packaging uses GPL Temurin JDK21 with matching runtime sources; preserve the MSI UpgradeCode and separate program/data paths. Publication and installer acceptance remain separate from preparing source/artifacts.
- 2026-10-27: Consolidate Android/Desktop Google identity and Firebase into `echo-85da4`, replacing the old Android OAuth registration after duplicate package/certificate rejection. Use the existing GPL-compatible platform/browser authentication rather than a proprietary identity SDK. Explicit Firebase consent covers playlists, favorites, saved metadata and bounded history; no audio/paths/credentials are transferred. Shared merge and guarded apply preserve duplicates, concurrent edits, unlikes, deletions and history clearing. Normal emulator/desktop/cloud equality passed; no physical phone was accessed.
- 2026-10-27: Windows keeps desktop navigation and LibVLC playback, reuses Android's icon, and supplies daily/manual update discovery independent of Android release ordering. Verify MSI size/hash/product/version/UpgradeCode/architecture before an explicit interactive installer launch; never silently replace running files or accept Windows prompts. Connected presence, synchronized audio and output routing remain separate work.

- 2026-10-26: Search taps replace only the current playback occurrence and preserve the upcoming queue. Playlist append offers normal/shuffled/recording-related smart order. Service-owned commands retain explicit shuffle traversal; random initial selection must be first in a complete shuffled traversal rather than accidentally skipping its prefix in repeat-off mode. Preserve occurrence duplicates and source validation. Add a service-owned monotonic sleep timer which pauses and keeps the queue; no system sleep settings or exact-alarm permission are required.

- 2026-10-26: Optional Google sign-in and private Drive account playlist sync follow the user's account/cross-device request. Keep listening available without an account. Require real owner OAuth configuration; disable unconfigured sign-in clearly. Separate authentication and Drive consent, require explicit confirmation before uploading the device library, retain local data on sign-out, exclude audio/likes/logs/device paths, qualify local track identities and preserve concurrent edits as conflict copies. Initial automatic sync runs only while foreground; unseen stale snapshots can resurrect deletions without global tombstones. See ACCOUNTS.md.
- 2026-10-26: Distinguish pinned offline downloads from an optional bounded frequent-song cache. Reuse existing resolvers and OkHttp, verify complete private files before playback, enforce storage budgets, cancel on offline/metered transitions and expose interrupted transfers as Retry. Do not promise closed-app completion or audio transfer between accounts/devices. See OFFLINE.md.
- 2026-10-26: Record actual starts/outcomes/listening duration with a non-destructive Room v1→v2 migration. Keep 90 days/5,000 events locally, display 500 and support confirmed clearing. Use conservative local preferences to nudge real related results, never replace them with unrelated search. Full player and queue recommendations share add-to-playlist controls. Recognized Google artwork resize variants request more detail with original fallback.

- 2026-10-25: Fix Home returning to a restored Library stack by removing top-level stack restoration. Use a compact 56dp navigation row above system insets and an immersive player without main navigation chrome. Queue UI follows the controller's true next-window order, distinguishes duplicate occurrences and keeps the current song visible. Manual matching remains for ambiguous recordings; clear import matches can run automatically with progress and an atomic stale-edit guard. Smart shuffle now seeds YouTube related results from a specific recording, preserves the current song/position when applicable and refuses unrelated search fallbacks.

- 2026-10-25: Accept full public Spotify playlist share links through bounded public HTML reads, with a user-confirmed preview of exposed versus declared total songs. Unknown/partial counts remain explicit; no account cookies, authentication bypass, internal API calls or Spotify audio are used. Imports create new snapshots through the existing transaction; file import remains available. Public HTML may change and does not establish universal playlist access or automatic synchronization.

- 2026-10-25: User has no Premium. Replace normal Spotify connection UI with local playlist-file import; retain prior credentials/auth implementation without making login a requirement. Imports are snapshots, transactional and additive with new playlist IDs. Select YouTube recordings explicitly per occurrence. Echo discovery and smart shuffle use artist searches, and New music uses a current-month search rather than claiming a verified release feed. This supersedes the onboarding UI decision below; Spotify automatic sync remains unavailable under the current setup.

- 2026-10-24: Use four meaningful modules rather than dozens of empty modules.
- Use installed Gradle 8.14, AGP 8.11.1 and SDK 36 when compatible; Java 17 bytecode.
- Local files are the first playback source. Online sources must document playback permission.
- Spotify uses authorization code + PKCE; YouTube discovery opens official external playback.
- 2026-10-25: At the user's request, replace key-based YouTube links with key-free NewPipe song search and lazy in-app audio resolution. Preserve stable video identities in existing storage; keep Spotify imports metadata-only. This supersedes the original external-only YouTube decision. Pin the extractor version and require real playback evidence after updates; do not promise all-song availability.
- 2026-10-25: GitHub updater targets public `addy1243/Echo` stable releases. Assets encode Android version code in `EchoMusic-<code>.apk`; SHA-256, package, version, SDK and installed signer checks precede Android's user-confirmed installer. Startup checks once daily; Settings can check immediately. No release was published.
- 2026-10-25: For Spotify onboarding, bundle Echo's owned public client ID at build time and use the fixed registered mobile callback with PKCE. Remove normal runtime developer fields; preserve HTTPS callback support internally. Dashboard acceptance/live OAuth require separate verification. This onboarding decision did not change YouTube; the user's subsequent return to YouTube scope is recorded in the key-free playback decision above.
