## Connected playback

On the same Google/Firebase account, each opted-in device shows the other player's current title/artist and offers play, pause, previous, next and ±10-second seeking. Android also shows a current-song banner that opens Profile controls. Windows exposes device cards in its sidebar and account dialog. Both players retain independent queues.

After updating **both** apps, enable **Profile → Connected playback** on Android and **Devices & account → Allow remote controls on this laptop** on Windows. Keep Android Echo open: this first version follows the Activity's STARTED lifecycle. The Windows app must remain running. Audio transport, synchronized groups and multiple output routing are separate future work.

The owner configured and published owner-only RTDB rules in `echo-85da4`; Firestore remains the library backend. Snapshots exclude audio, source URLs, paths and credentials. Commands have session/track/queue guards, expiry, deduplication and acknowledgments. See [the protocol, setup and privacy boundaries](../CONNECTED_PLAYBACK.md).

## Other changes

Desktop discovery now loads new music before a library exists, refreshes when synced artist seeds change, and ignores superseded results. Windows Firebase session reads avoid rewriting protected credentials on every playback poll. Native paused seeking updates the requested position and resumes from it; explicit play/pause commands are idempotent and apply under the audio dispatcher's stale-occurrence guard.
