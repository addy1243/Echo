## Changes

- Windows replaces the permanent remote-device card rail with a bottom player and compact device picker. Artwork/title have priority; offline devices remain under Other devices. Expanding Move or Together keeps the device list in place.
- Android mini and full player share the selected local or remote player. Devices, Move and Together are three circular labeled actions below transport. Inline choices scroll into view; the expanded mini controls are bounded and scrollable. The toolbar opens connected controls without requiring a local queue.
- Device selection changes what is viewed and controlled without moving audio. Reconnecting players retain metadata while commands are disabled. Remote seek and transport check the current selected device, session, occurrence and queue before dispatch.
- Remote metadata remains visible without a portable track ID; artwork uses an exact library match or a validated canonical YouTube ID.
- Correct the acceptance helper's bounded mailbox cleanup query. The owner-approved cleanup removed only three fingerprinted offline Windows test registrations; the real Firestore library contained no playback-test tracks.

## Capabilities and limits

Existing remote play/pause, previous/next and absolute seek are supported. Both native players retain independent audio sessions and queues. **Moving songs, Play together, audio relay and output routing remain unavailable**; the interface explains those limits. Android Echo must stay open for connected participation. Remote progress uses confirmed snapshots rather than acoustic synchronization.

Account playlists, favorites and history continue using the existing Firebase library sync. This release changes no database schema/rules, signing identity or credential storage. No physical phone was accessed. See [connected playback](../CONNECTED_PLAYBACK.md) and [the approved design](../CONNECTED_PLAYER_DESIGN.md).
