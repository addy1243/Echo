# Listening history

The playback service records one `PLAYED` event when audio actually starts for each queue occurrence. Pausing, buffering and replacing an expiring source do not create another play. Explicit moves to another occurrence record `SKIPPED`; automatic transitions and the final natural end record `COMPLETED`. Queue replacements record neutral `INTERRUPTED` events. Playback errors record `ERROR` without exposing signed URLs or exception text. Moving past an unrecovered failure is neutral rather than teaching a dislike; an explicit skip after successful recovery is preference evidence again. Repeats and repeated song IDs remain independent occurrences.

Listening time uses the monotonic clock only while the player reports actual playback. Preferences count substantive completions and listens of at least 30 seconds; early explicit skips reduce preference. Seeking directly to a song's end does not qualify as enjoying the song. A short recording can qualify after listening to half its duration. Errors do not reduce preferences. Existing likes stay independent.

Room v2 adds three columns to the existing history table through a non-destructive v1-to-v2 migration. Old events remain `PLAYED` with unknown time listened. No playlist, duplicate occurrence, favorite, credential or original track is removed. All database builders must register `MIGRATION_1_2`; production registration is in `LibraryRepository`.

`LibraryRepository.listeningHistory` exposes the latest 500 events with song metadata for UI; `listeningPreferences` computes per-track evidence from up to 5000 retained events. `clearListeningHistory()` clears events and preference evidence, leaving playlists and likes intact. New writes trim history to 90 days and 5000 events. Listening events stay on the device and are excluded from metadata backups and cloud playlist snapshots.

The History screen shows each event's song, outcome, listening duration and device-local timestamp, provides replay through the current library's playable source and asks for confirmation before clearing. Smart shuffle softly promotes candidates with positive track/artist evidence within the recording-related provider results; repeatedly early-skipped recordings with negative scores are excluded. Candidates can move only a few relevance positions. Existing playlists and their songs are never filtered by preference. Artist discovery seeds also respect preference evidence.

Tests added: `ListeningTrackerTest` covers pause/resume/retry accounting, duplicates/repeats, unplayed items and neutral failures; `ListeningHistoryTest` covers preference evidence and seek-to-end; `ListeningHistoryMigrationTest` checks actual v1 migration preserves duplicate playlists, favorites and old history and checks storage/clear behavior. `ListeningPreferencesTest` covers neutral-order stability, repeated skips and bounded artist promotion. Emulator-only `HistoryOfflineUiTest` checks persisted event display and recreation, disabled metadata-only replay, cancel/confirm clearing, Downloads/settings navigation and the disabled unconfigured Google sign-in button. The orchestrator runs integrated Gradle/device checks; addition of these tests alone is not evidence they executed.

Limits: process termination or service shutdown does not produce a false skip; the unfinished occurrence retains its start event but can lose its partial listening duration. History before this version cannot reconstruct skips/completions. Replacing a queue with the same current track can share its existing listening session, preserving source-retry/smart-shuffle behavior; ordinary repeats remain separate. Preference scores are bounded local heuristics, not a trained recommendation model or a guarantee of recommendation quality.
