# Windows updates

Current stable release: [0.2.1](releases/0.2.1.md). In an older Echo build, open **App updates → Check for updates**, download and choose Install; normal Windows Installer confirmation remains required.

The desktop updater is separate from Android APK updates. On startup it checks at most once per 24 hours; **Check for updates** performs a manual check. It reads a bounded listing of up to 100 public releases from `addy1243/Echo`, with no GitHub token, and selects the highest valid newer Windows version. Drafts, prereleases, Android assets, old/equal versions and invalid release entries are ignored. An Android-only newest release does not hide an older published Windows update.

An available update has explicit **Download** and **Install** actions. Downloading shows received/total bytes and supports Cancel. The app never replaces its own running files. Install re-verifies the staged file, then opens the normal interactive Windows Installer using `msiexec /i <file> /norestart`. It does not use quiet/passive options, accept Windows prompts, or promise installer completion. Close Echo when the installer requests it. The portable development image must be installed once through the MSI before later MSI upgrades update the installed copy; a checkout's generated EXE is a separate copy.

## Installer closes but the old version stays open

Check the running executable path. The MSI updates `%LOCALAPPDATA%\EchoMusicDesktop\EchoMusic.exe`; a project-generated portable EXE is a separate copy. A successful repair/reconfiguration may close normally while that older portable app remains open. Close it, launch the installed EchoMusic shortcut and verify **App updates → Installed version**. Correct any personal shortcut that still targets the project folder; preserve the shared `%LOCALAPPDATA%\EchoMusic` data directory.

On 2026-10-29, Windows Installer events reported successful 0.2.1 reconfiguration (status 0), the installed executable/configuration and registry reported 0.2.1, and the launched installed app displayed **Installed version 0.2.1** with the existing library present. The top-level personal Start-menu shortcut had targeted the old project image; it was corrected to the installed EXE. This verifies this user's installation/launch, not an upgrade between two previously registered MSI versions.

## Release contract

- Current desktop version: `DESKTOP_VERSION` in `DesktopUpdater.kt`; keep the Compose `packageVersion` identical. Desktop semantic versions use three numeric components and MSI limits: major/minor ≤255, patch ≤65535. Increase that version for every Windows release.
- The release asset must be **`EchoMusic-Windows-x64-<version>.msi`**, for example `EchoMusic-Windows-x64-0.2.1.msi`. The GitHub asset must be uploaded and expose an exact size (maximum512MiB) and `sha256:` digest. The URL must point directly to that filename under `https://github.com/addy1243/Echo/releases/download/<tag>/`.
- Android and Windows assets may be published on separate releases/tags. The Windows MSI must remain among the first 100 releases returned by GitHub; discovery uses one request and a 2MB response cap. Add bounded pagination if that window becomes too small. Do not publish a dummy installer or change immutable existing release assets merely to make a check return Available.
- The MSI must identify **ProductName `EchoMusic`**, **ProductVersion equal to the asset version**, **x64 architecture**, and **UpgradeCode `{A810BA6C-3581-4E29-A09D-F344CA0230AD}`**. Configure that UUID in `nativeDistributions.windows.upgradeUuid` and retain it for all subsequent Windows versions. ProductCode may change between versions.
- Configure `nativeDistributions.windows.installationPath = "EchoMusicDesktop"` and `perUserInstall = true`, placing program files in `%LOCALAPPDATA%\EchoMusicDesktop`, separate from `%LOCALAPPDATA%\EchoMusic` library data and credentials. The setting belongs inside `windows` in the pinned Compose1.8.2 plugin. Inspect the actual MSI Directory table to confirm this; configuration text alone is insufficient. Keep installer directory customization disabled to avoid accidentally selecting the data directory. The installer must never package/uninstall the existing library or credential directory.

Every request and redirect is restricted to HTTPS and GitHub's configured download hosts, with no embedded user information, alternate ports or URL fragments. Redirect count, response size, installer size and timeouts are bounded. Rate-limit cooldown persists. The exact downloaded length and SHA-256 must match GitHub's release metadata; Windows Installer's read-only COM API then checks product/version/upgrade identity and architecture. The complete MSI and its release metadata are staged under `%LOCALAPPDATA%\EchoMusic\updates`, outside the installed program. Restart and Install both recheck the file and MSI identity; interrupted or rejected files are not offered for installation.

This repository has no configured Windows Authenticode signing identity yet. HTTPS, repository ownership, GitHub's digest and MSI identity checks are the current trust boundary; a repository-owner compromise is not mitigated by an independently pinned signing key. Do not describe the MSI as signed, suppress Windows's unsigned-publisher warnings, or claim the checksum alone authenticates a publisher. Add publisher signing and a reviewed signer-pinning policy when distributing signed builds.

## Verification

Focused `DesktopUpdaterTest` covers independent Android/Windows release selection (including a newest Android-only release), highest valid Windows version, bounded listing, size/digest/URL boundaries, daily/manual checks, redirect host rejection, persistent rate-limit cooldown, verified download and restart, tamper rejection at installation, MSI identity, and cancellation of a blocked real loopback HTTP response. No test accepts a Windows installer or changes an installed application.

Windows 0.2.0 is published in [v0.2.0](https://github.com/addy1243/Echo/releases/tag/v0.2.0). The production updater simulated an older 0.1.0 preview, detected the release, downloaded the public MSI and passed exact size/SHA-256 and native identity verification. No installer was launched. Actual Windows installation/upgrading and library/credential retention through it remain separate acceptance checks. See [the full release record](releases/0.2.0.md).

On 2026-10-27 the generated local MSI was inspected through Windows Installer COM without installation: ProductName `EchoMusic`, version0.1.0, expected UpgradeCode and x64 template matched. The production Java/PowerShell verification helper passed against the actual final MSI. Read-only Directory/RemoveFile/CustomAction/Registry table review found removal targets confined to the installed program subtree and its Start-menu directory. Recursive uninstall uses the package's recorded `INSTALLDIR`. The rebuilt MSI Directory table confirms `LocalAppDataFolder\EchoMusicDesktop`, separate from `%LOCALAPPDATA%\EchoMusic` data. No installer was accepted, no installed registry values were queried and no user library was changed by this inspection.
