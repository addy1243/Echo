# Player playlist actions and artwork

The full player and every visible queue occurrence now offer Add to playlist. This includes recommendations inserted by smart shuffle: playback persists those tracks before queue submission, so the same durable Track identity is saved. The existing track-list action shares the same picker. Users can also create a playlist directly from the picker; creation and the first song import use the existing atomic repository transaction. Repeated additions retain duplicate occurrences.

Artwork was already selecting the largest trusted image exposed by the provider. Small YouTube Music artwork persisted as a Google image resize URL could still be enlarged in the player. For the full-size player only, recognized HTTPS Google image resize suffixes request 1200 by 1200 pixels, with one fallback to the original supplied URI on failure. Local art and other URL formats are unchanged; this cannot invent detail absent from the original image. Metadata and backups retain the supplied URI. Upstream format changes simply retain/fall back to the supplied image; arbitrary URLs, ports, credentials and signed queries are not rewritten.

Added checks: ArtworkQualityTest covers recognized resize URLs and unchanged local, unrelated, insecure and signed URLs. NavigationPlayerTest's shuffled duplicate queue scenario now saves the current song twice and saves an upcoming occurrence, then checks durable playlist order and duplicate preservation. It uses generated local audio on a dedicated emulator and cleans its own fixtures.

The orchestrator's integrated JVM and emulator checks passed; see INTEGRATION_STATUS.md for executed evidence. The new requested image variant has not been compared visually over a live connection, and unavailable high-resolution originals remain a provider limit.

## Account snapshot merge helpers

`account/PlaylistSyncMerge.kt` merges complete playlist snapshots against a last-seen baseline. A one-sided change or deletion propagates when the other side still equals baseline. Concurrent edits keep the local playlist and retain the remote version under a deterministic content-hashed conflict ID. Repeated merges reuse an equal conflict copy. A concurrent edit wins over deletion, preserving user data for manual resolution. Track occurrence order, duplicates and Spotify playlist metadata are retained. Seven JVM tests cover merges, deletions, conflicts, retries and metadata.

`account/CloudPlaylistSnapshot.kt` adapts existing version-1 library backup JSON to playlist-only cloud data. It keeps only referenced metadata; favorites, listening history, local mappings, device artwork/source paths and unknown fields are excluded. Local and Spotify sources are always null. Only canonical stable YouTube identities and HTTPS `upload.wikimedia.org` audio URLs survive as playable sources. Other HTTPS artwork/source-credit links must have no embedded credentials, nonstandard port or fragment. Merging metadata gives the local device priority for existing track IDs. Four Android JSON adapter tests were added; live account/Drive behavior belongs to the orchestrator's integration work.

Cloud-local qualification uses an originating installation UUID so another phone's MediaStore ID can never silently resolve to this phone's unrelated song. Already-qualified records retain that origin when forwarded by other devices. Only the owning installation restores those identities before its guarded local transaction. Two Android checks cover namespace round trips, duplicate occurrences and invalid prefixes. Three in-memory Room checks cover cloud application preserving local URIs, likes and local matches, explicit deletions, stale-edit rejection and complete rollback on an entry-write failure.
