# Echo Music architecture

The four Android Gradle modules remain `core` (pure Kotlin contracts), `data` (Room, MediaStore, settings and integrations), `playback` (Media3 service and Android Auto), and `app` (Hilt composition and Compose screens). A separate `desktop` Compose JVM module reuses core models and selected pure provider, matching, preference and Firebase sources, with Windows-specific persistence, LibVLC playback, account and updater adapters. Android data is not moved into desktop storage.

Queue append/search-selected/fresh-shuffle commands run in the service and are available only to the same package/UID. Requests contain bounded stable library IDs; all sources resolve before mutation. Explicit ExoPlayer shuffle permutations preserve actual traversal and ensure a random initial occurrence remains first in a complete shuffled session. Playlist append preserves existing traversal even across repeat-all wrap. `SleepTimerController` exposes a monotonic in-process deadline; the service ticks and pauses on expiry, keeps the queue intact and clears the timer on destruction. See [queue contract](QUEUE_ACTIONS.md) and [sleep lifecycle](SLEEP_TIMER.md).

The 0.1.7 history migration adds outcome/listening-duration fields to the existing history table using an explicit v1→v2 Room migration. The service owns actual listening-time accounting; bounded local logs produce preferences for small ranking adjustments within recording-related results. History remains excluded from file backups; explicit Firebase sync now shares bounded stable history events and account-wide clear revisions. See [event semantics](HISTORY_NOTES.md) and [Firebase contract](FIREBASE.md).

`OfflineRepository` owns private complete audio, a durable manifest, serialized cancellable transfers, separate pinned/cache budgets and integrity verification. The resolver checks saved files before online extraction. Offline mode blocks remote audio opens; automatic cache eligibility depends on substantive listens, explicit opt-in and validated unmetered connectivity. Neither downloads nor signed URLs enter Room/backups. See [offline design](OFFLINE.md).

Google authentication uses Android AccountManager and the installed Google authenticator, or desktop browser PKCE, with verified identity. Proprietary Google identity SDKs are not bundled. Both exchange Google credentials for Firebase sessions in the single `echo-85da4` project. Shared REST/schema/merge code synchronizes one bounded owner-only Firestore library document, using optimistic revision checks, deterministic playlist conflicts, deletion/unlike markers, stable history identities and clear revisions. Platform adapters capture baselines, guard intervening local edits and apply atomically while retaining local file associations. Audio, credentials, local paths and signed streams are excluded. Automatic sync runs only while open/foreground and enabled. Existing `DrivePlaylistSync` snapshots are retained as legacy data; current account UI uses Firebase. See [accounts](ACCOUNTS.md) and [exact sync contract](FIREBASE.md).

Windows update discovery scans a bounded public release listing independently of Android releases. Downloads validate GitHub hosts, exact size/hash and native MSI identity; verified staging survives restart and installation remains explicit through Windows Installer. The per-user program directory is separate from library/credential storage. Desktop and Android use the same waveform icon, rendered reproducibly into PNG/ICO assets. See [Windows release/update contract](DESKTOP_UPDATES.md).

Track metadata merge respects one-sided changes against the baseline and uses a deterministic winner for concurrent differences. Android accepts canonical remote metadata while retaining its own local file associations and match rows. History retention orders listening timestamps rather than insertion IDs, and an account-clear revision clears the complete local history table and identity mappings before importing the new epoch. These release fixes retain Room schema version2 and its non-destructive migration.

Playlist-file parsing (Spotify account JSON / Exportify CSV) stays in `data`; the repository imports all playlists atomically with new IDs. Explicit recording selection replaces one guarded playlist occurrence with a canonical YouTube track. Discovery uses the existing provider's artist searches; pure app helpers filter discoveries and interleave queue entries. No schema migration, automatic Spotify sync, extra backend or new dependency is required.

Public Spotify share links are previewed through bounded, canonical-host HTML reads in `SpotifyPlaylistLinks`. Embed metadata and an independently declared public-page total produce a complete/partial/unknown preview. The UI requires confirmation before using the existing atomic playlist import; auth code and playback resolvers are unchanged.

Canonical model: `dev.echo.core.Track`; URIs are strings at domain boundaries. Spotify metadata may have no audio URI. Duplicate playlist occurrences use independent positions. No destructive database migration or client secrets.

Automatic recording matching uses conservative title/credited-artist/duration comparisons, preferring an unambiguous recording or consistent duplicate uploads. The ViewModel runs bounded per-playlist searches with progress/cancellation, then commits replacements only if the playlist's ordered IDs still match the captured snapshot. Duplicates and original metadata remain, and likes are copied to matched canonical IDs without removing old favorites. No database schema change.

The app observes MediaController events to snapshot current/upcoming entries using the player's actual timeline, shuffle order and repeat-all traversal. Window UIDs guard stale actions; Compose uses saveable integer occurrence keys. The player is a full-screen route with its own queue sheet. Bottom-tab navigation pops to Home without restoring other tabs' nested stacks.

The service owns ExoPlayer. The phone UI connects with MediaController. Car browsers use the same MediaLibraryService and durable library.

YouTube uses NewPipeExtractor for key-free song search and stream resolution. Persisted tracks contain stable provider/video IDs and canonical watch links. The service resolves temporary audio URLs lazily through a Media3 resolving data source, keeping them out of Room and backups. Local files and Commons retain their provider paths; Spotify imports remain metadata-only until locally matched. See [integration setup and maintenance](INTEGRATIONS.md#key-free-youtube-playback) and [release history](../CHANGELOG.md).
