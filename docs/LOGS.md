## 2026-11-06 — Adaptive Play together design and timing

- Astra medium reviewed the timing architecture. Start, Sync, and shared-queue replacement now use one bounded future deadline sized for the slowest fresh member session, using control RTT, jitter, clock uncertainty, polling, and a safety margin. The coordinator projects its playhead to that deadline; each client schedules against monotonic time and validates the exact group, session, timeline, and occurrence. Missing or warming-up estimates use the 8-second fallback. This avoids treating ping as speaker delay and does not promise acoustic synchronization.
- Added matching Windows and Android presentation: a distinct tinted group player, member readiness and session-matched timing details, a single `Sync now` action with an `Adjusting timing…` state, and copy that identifies network estimates rather than speaker/output latency. Stage Admin provides simulated 20 ms, 500 ms, and variable estimates without Gmail or live network access.
- Hardened group queue replacement to prepare each member before commit, preserve order and duplicate occurrences, retain the old queue on precommit failure, and report partial activation after commit. Leaving a Stage group restores private queues paused. Added regression coverage for adaptive projection, scheduled replacement, Stage estimate freshness, and Android Stage Sync readiness.
